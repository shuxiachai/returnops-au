## Scope and private interface

`compose_private_pass_review(engine, controlled_adapter)` returns a `PassReviewReceiver` with `accept(case_id, expected_case_version, original_key, correlation_id)` and `recover(case_id, expected_case_version, original_key)`. Composition follows the existing private REVIEW service pattern. It takes no human authorization token because this service must hold its own current `controlled-pass-review-v1` REVIEW grant. It neither grants authority nor substitutes for a Founder F.03 decision.

The caller cannot supply a review, proposal, actor, grant, target state or adapter choice through the business request. Trusted local composition supplies the explicit synthetic adapter. The entry has no public route, default producer, model call, C implementation, preview, APPROVE/REJECT, provider dispatch or notification sender.

A new intent requires exact modern 0008, available current RISK_REVIEW, the actual complete accepted proposal and customer/upload/intake/order/proposal chain. PASS or PASS_WITH_WARNING enters AWAITING_APPROVAL. Case version increments once; input version, generation and proposal identity/version remain unchanged. The transaction saves immutable review history, finite encoding, causal audit, PRIMARY proposal binding, current review pointer and completed REVIEW work. It creates no decision, approval, operation, outcome, notification or corresponding work.

## Controlled positive family and exact context

The private receiver accepts only `synthetic-cups-pass-v1`: two chipped cups under an explicitly synthetic free simulated return policy. Test-only `SyntheticCatalogue`, `build_positive` and `ControlledPassReviewer` live in `tests/lifecycle/pass_review_helpers.py`; the private R.02 driver uses an unchanged, likewise unpackaged copy of `build_positive` and `ControlledPassReviewer` in `tools/r02/scenario.py` (with a fixed-identity cups catalogue in `tools/r02/catalogue.py`); none of them is installed or registered by default. Customer upload and creation supply actual evidence identity, bytes, length and hash. Intake and `InvestigationProcessor(catalogue=...)` produce real lookup receipt/projection; `FixedProposalProcessor(build=...)` produces the actual accepted proposal work, claim, history, audit, binding and event.

The builder consumes and retains the full `RetainedMaterial`. `pass_scenario.verify_scenario` is a narrow acceptance oracle, not a live risk policy or another production builder. It checks exact synthetic facts, selected quantities, full evidence matrix, policy bytes/version/hash, citations, conditions, action, uncertainty, original synthetic statement and proposal ModelRun metadata. A default manual proposal cannot be relabelled as positive. Unknown or additional material is rejected rather than truncated, hidden or converted to support. Each PASS and warning positive uses a separate case and proposal.

The receiver forwards the complete retained bundle to the adapter. The server fixes review ID, time and complete ModelRun: provider `fixture-no-live-model`, model `controlled-synthetic-pass`, prompt `controlled-pass-v1`, role RISK_REVIEWER and zero tokens. All returned metadata must equal that exact invocation; input/context mutation and extra wire metadata are rejected. The frozen RiskReview and ModelRun schemas are unchanged. No trace field is added.

PASS permits only INFO findings and empty questions/revision requests. PASS_WITH_WARNING requires at least one WARNING, permits only INFO/WARNING and also requires empty questions/revision requests. References must belong to the full packet. The receiver does not implement C's independent risk assessment or establish C's acceptance of this synthetic family.

## Proof, final fence and event isolation

Outer receiver and lower guard independently verify accepted proposal/review work, original claim/epoch, causal audit, binding, order projection and event receipt. `PassReviewAccepted` has the distinct persisted event kind `REVIEW_PASS`, including that kind in its fingerprint. The old ESC event remains `REVIEW` and ESCALATED. Same-shaped event classes therefore cannot exchange receipts. Old ESC/manual/revision source validators retain their separate scope.

Current grant/revision, owner/store, available head/state, input/generation/version and the original unextended lease are rechecked after expensive source reads before commit. The lower guard also checks the sealed source/work/state and exact schema. A failure rolls back all original business changes, even if a caller catches the exception.

Founder current projection selects its proof reader using the immutable origin plus persisted component/work/event identity. It never chooses a weaker validator from the review's outcome string. The validated warning and historical versions remain readable; queries create no business work, grant or state transition. Existing Founder pagination may create its own read metadata as documented by the read-query component.

## Idempotency, UNKNOWN and retention

The original key binds the original version and work identity. Exact replay validates the complete original acceptance proof and returns the original receipt without invoking the adapter. Different keys cannot take over an existing target, and another component cannot take over REVIEW work. Historical source verification does not grant authority for a new intent.

Ambiguous acceptance returns UNKNOWN with no automatic retry, replacement key or denial audit. Fresh recovery checks current authority and original facts; missing facts remain UNKNOWN. Only separately proven rollback permits an explicit caller retry. Deterministic rejection exits the original UoW before fresh REVIEW authorization for a bounded denial audit. Missing current authority records no case audit; ambiguous audit commit remains UNKNOWN.

Existing retention removes derivative proposal/review bodies and receipts without reconstructing them from fixtures, cache or old receipt data. No post-AWAITING_APPROVAL decision is added here, so there is no claimed positive later business transition merely to exercise historical replay.
