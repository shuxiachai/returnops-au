# A1.05 offline fixed-proposal preparation

This is a local, synthetic preparation tool for A1.05. It creates a separately
labelled copy of a complete `HistoricalProposalBundle` after comparing it with
an independent retained fixture inventory. It does not implement or accept the
A1.05 API/worker path. The original WBS remains A1.05, Owner A / Reviewer C,
S = A1.03, F = A1.04 and F.03; the nine features and 89 fixed WBS rows are unchanged.

The original A1.03 Owner decision, designated C's personal review and predecessor
accepted-version records remain pending in the current acceptance packet.
`whole_A103_accepted=false` and `runtime_unlocked=false` remain unchanged. This
fixture work supplies no person, predecessor or whole-item acceptance.

## Scope and entry point

`tools/offline_fixed_proposal.py` exports one preparation function:

```python
result = assemble_offline_proposal(candidate_bundle, source_inventory)
assert result["label"] == "OFFLINE_SYNTHETIC_NON_EXECUTABLE"
bundle = result["bundle"]
```

`candidate_bundle` uses the existing frozen `HistoricalProposalBundle` /
`DecisionPacket` shape. The function calls the existing
`returnops_domain.founder_codec.validate` and
`returnops_domain.founder_history_types.proposal_bindings`. No alternative schema,
capacity limit or production package export is added. The output bundle has the
same fields as the validated input and shares no mutable object with either
input. The outer label is preparation metadata, not a new wire-schema field.

The tool accepts a fixed Assessment candidate with `provider-fixture`,
`fixture-no-live-model` and zero input/output tokens. Those fields explicitly
mean that no model inference took place. Retrieved passages must also be marked
synthetic. Tests reuse `contracts/v1/examples.json`'s `history-proposal.content`
and its existing contract oracle; the original fixture file is unchanged.

## Independent synthetic source inventory

The inventory is a separate input captured before preparing or modifying the
candidate. It must not be generated by trusting the candidate's own source list.
It has the following exact shape; `image_observations` alone is optional:

```text
label: OFFLINE_SYNTHETIC_SOURCE_INVENTORY
case_id, input_version, proposal_id, proposal_version,
corpus_version, original_statement_id
statements: [{value: complete CustomerStatement DTO, fingerprint: digest(value)}]
attachments: [{value: complete EvidenceAttachment DTO,
               fingerprint: digest(value), content: retained synthetic bytes}]
order_lookup: {value: complete OrderLookupResult DTO, fingerprint: digest(value)}
retrieval_result: {value: complete RetrievalResult DTO, fingerprint: digest(value)}
image_observations: {value: complete ImageObservationResult DTO,
                     fingerprint: digest(value)}
```

`digest` is the existing Founder finite codec's `history/finite-v2` fingerprint.
Complete DTO and inventory identity comparisons use that same typed fingerprint:
booleans cannot equal numeric fields, while the existing finite codec retains
its legal integral `1` / `1.0` normalization. No second codec or schema is added.
It is not an HTTP JSON hash or RFC 8785 claim. Passage content hashes use SHA-256
of the complete UTF-8 text. Attachment size and SHA-256 must match the retained
bytes; bytes are checked without becoming a new field in the output bundle.
The tests use explicitly synthetic bytes to exercise integrity, not image
recognition or file-format validation.

All original and clarification DTOs, including the original raw text and any
original requested outcome, remain distinct from extracted facts and proposed
actions. Full ordered collections must match the independent inventory,
including unreferenced clarifications and attachments. The inventory requires
full retrieval DTOs, so uncited passages, `NO_MATCH`, conflicts and timestamps
cannot be dropped. Optional image observations are either present and complete
in both inputs or absent in both. Duplicate statement, attachment, citation,
verification and passage IDs are rejected.

The packet, inventory and relevant source DTOs must agree on exact case/input,
proposal/version and corpus bindings. Every citation must resolve to exactly one
retained passage with matching document ID, source version (including a declared
null when the frozen contract allows it), corpus, location and content hash.
Every cited ID requires one `VALID` fixture check. These checks establish fixture
consistency only; they do not decide whether a recommendation is sound or whether
a conflict is blocking.

A self-consistent inventory is not proof of current source retention, corpus
review, authorization, an accepted order projection, or permission to publish a
proposal. Runtime source checks remain in `lifecycle_proposal.verify` and are
not called here. The offline tool never rewrites an order receipt's source input
n into candidate input m. A mismatch is rejected; there is no fabricated accepted
projection or receipt.

## Missing information and capacity

Missing or altered required retained source material rejects the whole draft
with a static `OfflinePreparationError`; no partial output or truncated preview
is returned. Caught parser/encoding failures are converted only after leaving
the exception handler, so the rejection does not retain their cause or context
(including source text held by `UnicodeEncodeError.object`). Frozen DTO validation enforces existing text and array capacities.
At the exact boundary, the complete content survives unchanged; an over-limit
input is rejected. This tool creates no runtime failure event or manual-handling
state, since it owns no runtime transaction.

A complete retained bundle may truthfully contain `MISSING` or `CONFLICTING`
business criteria, `NO_MATCH`, conditions and unresolved questions. Those values
are preserved in the non-executable draft for later independent Risk review.
The tool does not change them into PASS, issue an approval or create a command.
The same non-executable label applies to every result, including a supported
fixed recommendation.
